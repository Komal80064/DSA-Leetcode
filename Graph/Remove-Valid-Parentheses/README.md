# Remove Invalid Parentheses — BFS Approach

### Pattern

**BFS + String Manipulation + Validation**

---

## 🧠 Problem Idea

Given a string containing parentheses and possibly other characters, remove the **minimum number of invalid parentheses** so that the resulting string becomes valid.

We need to return **all possible valid strings** after the minimum number of removals.

Example:

```text
Input:
()())()

Output:
()()()
(())()
```

---

## 💡 Intuition

Think of every string as a **state**.

From one string, we can create the next state by removing **one parenthesis**.

```text
Original String
      ↓
Remove 1 parenthesis
      ↓
All possible strings
      ↓
Remove 1 more parenthesis
      ↓
More possible strings
```

This forms a **BFS tree**.

Since BFS explores level by level:

```text
Level 0 → 0 removals
Level 1 → 1 removal
Level 2 → 2 removals
Level 3 → 3 removals
...
```

The **first level where we find valid strings** represents the minimum number of removals.

Therefore, once a valid string is found at a level, we don't generate the next level.

---

## 🔍 How to Check a Valid Parentheses String

Use a `count` variable.

```text
'(' → count++
')' → count--
```

While traversing:

```text
count < 0
```

means we have encountered more closing parentheses than opening parentheses.

Therefore, the string is immediately invalid.

At the end:

```text
count == 0
```

must be true.

### Two Conditions for Valid Parentheses

```text
1. count must NEVER become negative.
2. count must be 0 at the end.
```

Example:

```text
()()

count:
1 → 0 → 1 → 0

Valid ✅
```

Example:

```text
())(

count:
1 → 0 → -1

Invalid ❌
```

## 🚀 BFS Steps

### Step 1: Initialize

Create:

```java
Queue<String> q
Set<String> visited
List<String> result
```

Add the original string:

```java
q.add(s);
visited.add(s);
```

---

### Step 2: Process BFS

Take one string from the queue:

```java
String curr = q.poll();
```

Check whether it is valid:

```java
if (isValid(curr)) {
    result.add(curr);
    found = true;
}
```

---

### Step 3: Stop Going Deeper

If a valid string is found:

```java
if (found)
    continue;
```

Why?

Because BFS guarantees that all strings at the current level required the **same number of removals**.

Generating another level would mean making **more removals**, which is unnecessary.

---

### Step 4: Generate Next States

Remove one parenthesis at every possible position:

```text
()())()

Remove index 0 → )())()
Remove index 1 → (())()
Remove index 2 → ()))()
...
```

Only remove:

```text
'(' or ')'
```

Don't remove normal characters.

---

### Step 5: Avoid Duplicate Strings

Different removals can produce the same string.

For example:

```text
(())(
```

Removing either of the two identical `(` characters can produce the same result.

Therefore, use:

```java
Set<String> visited
```

This prevents processing the same string multiple times.

---

## 🔑 Core Idea

```text
BFS Level
    ↓
Remove exactly 1 parenthesis
    ↓
Check all resulting strings
    ↓
If none are valid
    ↓
Go to next level
    ↓
Remove 1 more parenthesis
    ↓
First valid level = minimum removals
```

---

## Example

Input:

```text
()())()
```

BFS starts with:

```text
Level 0:
()())()
```

Not valid.

Generate strings by removing one parenthesis:

```text
Level 1:
)())()
(())()
()()()
...
```

Valid strings found:

```text
(())()
()()()
```

Since valid strings were found at **Level 1**, we stop.

Therefore these are the answers requiring the **minimum number of removals**.

---

## ⏱️ Complexity

Let `n` be the length of the string.

There can be many possible strings generated by removing characters, so the worst-case complexity can be exponential.

A commonly stated upper bound is:

**Time:** `O(n × 2^n)`

**Space:** `O(2^n)`

The extra `n` factor comes from checking/generating strings of length up to `n`.

---

## 🧠 Revision Trick

Whenever you see:

> "Remove the minimum number of characters/operations to make something valid"

and each operation creates a new state:

Think:

**BFS → Level = number of operations**

```text
0 removals
    ↓
1 removal
    ↓
2 removals
    ↓
...
```

The **first valid level gives the minimum operations**.

# ⚠️ My Mistake — Remember This!

I initially thought:

```text
()())(
```

was a valid parentheses string because the final `(` seemed to balance the extra `)`.

But that's WRONG.

Check it step by step:

```text
String: ( ) ( ) ) (
        ↓ ↓ ↓ ↓ ↓ ↓

count:  1 0 1 0 -1 0
              ↑
         becomes -1
```

At the 5th character:

```text
)
```

we get:

```text
count = -1
```

That means there are **more closing parentheses than opening parentheses at that point**.

So:

```text
()())(
```

❌ **Invalid**

Even though the final count becomes `0`, it is still invalid.

### Golden Rule 🔥

> **For valid parentheses, count must NEVER become negative, and count must be 0 at the end.**

```text
Never negative + End at zero = Valid Parentheses
```

**Remember this mistake: final `count == 0` alone is NOT enough!**
